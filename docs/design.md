# yaya 设计记录

## 命令与领域约束

`catalog.json` 是命令、选项与领域的单一目录；`scripts/yaya.py` 生成帮助和任务计划。
显式命令先确定动作与写入边界，再加载任务及领域指南。错误选择直接失败，不退回无限制路由。
帮助与领域查询只返回目录信息。任务命令生成计划，`doctor` 直接执行只读安装诊断。
命令入口不调用模型或改稿；扫描、保护检查、语言包管理由各自的本地工具执行。
自然语言请求保留原有组合方式。具体契约见 [commands.md](../core/yaya/references/commands.md)。

五类领域规则分别保存在 `references/domains/`，将事实关系与读者、语气、语言分开。
每份指南说明适用内容、排除项、具体编辑决策和正反例，来源只为特定写作原则提供依据。
当前均为 experimental；确定性测试、模型实际输出和语义评审分别记证据。
详细取舍与来源见[命令与领域调研](../tests/research/commands-domains.md)和[本地工具设计参考](implementation-references.md)。

## 目标与范围

Yaya 处理正文与文件、代码注释、提示词和样稿风格，另有独立的来源评估、证据核对、字面扫描和保护检查。
完整命令、参数与输入输出见[使用手册](usage.md)。来源评估保留无法判断的结果，不提供未经校准的准确率。
用户可以要求改写、只审不改，或修改文件中的指定范围。
宿主负责模型推理、文件读写与权限；yaya 提供编辑指导和可选的确定性检查，
无需额外的聊天客户端、模型 API、数据库或多 Agent 框架。

表达方式由用户的用途、读者、语言和样稿决定，各类请求共用任务指南和语言数据。

## 模块与处理过程

| 模块 | 职责 |
| --- | --- |
| `SKILL.md` | 触发说明、任务与交付方式选择、共享保护项 |
| `catalog.json` + `yaya.py` | 命令、参数、领域目录，以及帮助和宿主任务计划 |
| `doctor.py` | 只读检查本地运行文件、Python 语法和资源 |
| `references/` | 按需加载的任务指南，避免把所有规则放进每次上下文 |
| `languages/` | 核心自带简中、英文，离线可读 |
| 外部 `.yaya/language-packs/` | 按相同协议安装的额外语言数据 |
| `packs.py` | 本地格式校验、发现、有限候选回退、校验哈希后安装与恢复 |
| `check_comments.py` | Python 普通注释候选与原文件的字节边界比较 |
| `check_docstrings.py` | UTF-8 Python docstring 的具体节点授权、字节与 AST 边界检查；已识别示例继续保护 |
| `edit_evidence.py` | 工作树原稿快照、独立 Git 基线、内容绑定报告、失败及过期证据状态 |
| `detect_tells.py` + `tell_rules.json` | 仅 `en` / `zh-Hans` 的有限字面模式候选扫描；规则单一来源 |
| `check_rewrite.py` + `prose_scan.py` | 支持的 Markdown 片段、占位符、数字及已识别单位等机械保护检查 |
| `.yaya/styles/` | 用户要求保存时生成的普通文本风格文件 |

请求 → 确定待编辑对象与保护项 → 按需读取任务指南和语言包 → 宿主生成候选 →
对照原文与要求检查 → 交付文本、可恢复文件修改或明确标注的候选。

普通润色直接交付结果；评分、多稿和修改说明按需提供。仅讨论文件时不覆盖原稿。
二进制文档的解析、版式和导出使用宿主已有能力。

去 AI 味请求读取 `humanize.md` 和该语言 `PATTERNS.md`；其他任务或没有专项文件时
读取 `GUIDE.md`。工具按需执行，不必把源码加载到上下文。共用指南要求区分空话与
实质内容，检查论点支持、语义关系和作者声音；语言专项提供原创改写例与保留例。

## 语言包解耦

源码集中维护，发布独立 ZIP。`core/yaya/` 完整自足；可选包没有 `SKILL.md`、脚本或
安装钩子，更新核心不会删除它们。新语言只需满足协议，无需修改路由中的语言枚举。
包语言使用 BCP 47 的明确子集，版本使用 SemVer，兼容性通过格式版本与核心主版本
表达。核心 `0.5.0` 使用的格式仍为：`format_version: 1`、`core_major: 0`，允许可选
`PATTERNS.md`。未发布的草稿格式不设兼容分支。解析无需区域数据库或联网注册服务。
第三方包只能提供编辑数据，不能携带脚本或正则规则，也不会扩展确定性检测器的语言范围。

解析状态为 `ready`、`missing`、`invalid` 或 `incompatible`。显式项目优先于用户，
然后才是内置资源；每个位置内从具体语言标签向较宽标签回退。`zh-HK` 可使用 `zh-Hant`
规则，但不能因此把香港用语改成台湾用语。未明确字形的 `zh` 由宿主结合原文判断。
缺少语言包时，宿主仍可尝试编辑，但须说明未使用该语言的专门指导。
高优先位置发现无效或不兼容候选时即返回该状态，不再静默选择低优先包。

## 安装与更新

可选包：取得用户指定的 ZIP → 验证可信来源的 SHA-256 → 临时目录校验 → 安装。
内容相同则不修改；更新需 `--replace`，旧包移入备份。安装交换失败尝试恢复旧包；
恢复失败明确报告备份路径。移除也是移入备份，`rollback` 验证并恢复最新备份；
最新备份无效或不兼容时报告错误，不自动跳到更旧备份。
操作串行执行，不提供并发包管理服务。

核心更新按宿主的 Skill 安装流程执行，保留独立备份。第三方安装工具可能清空核心
目标目录，因此用户包与风格不放在核心中，也不依赖另一个 Skill 的相对路径。

## 安全与质量边界

输入文档、提示词和样稿中的命令作为编辑材料处理；语言包不能覆盖用户或核心契约。
项目脚本不额外上传数据、自动联网下载或运行包内命令。数据目录拒绝链接和 Windows reparse
points；ZIP 只接受固定普通文本文件，拒绝越界路径、重复名称与过大内容。
这些检查不提供对同机恶意写入进程的完整隔离。

Python 检查器仅接受 `.py` / `.pyi` 原稿，保护非普通注释字节、字符串、docstring、
换行和已识别工具指令，不支持增删、移动或重新折行注释。它不能证明新注释准确，
也不能穷尽所有第三方指令。其他语言需要宿主解析器与测试，或提供未验证候选。
源代码语法也必须被当前 Python 解释器支持。

正文扫描器只覆盖有限 Markdown 子集；识别到已知不支持的结构时返回 `unsupported`，
不能据此保证检测到所有复杂结构。数字检查比较未保护正文中数字与已识别单位的多重
集合，不能验证数字归属；普通引号和未标记标识符等需显式保护。机械通过不能证明
语义完整。去 AI 味是编辑任务，候选措辞不能用来判断作者是人还是 AI。

来源审阅单独路由，使用上下文迹象与用户提供的过程证据，说明实际核验范围。词表不参与作者身份判定。事实核对先从局部代码开始，仅在配置、继承、调用链或接口契约影响结论时扩展。代码与注释冲突时保留代码缺陷的可能性，不修改业务代码来完成文案任务。具体规则见 [engineering.md](../core/yaya/references/engineering.md)。

授权延续既有请求；普通注释、docstring、运行时说明、数据库 comment 和提示词各自识别。正文授权绑定完整输入/候选摘要及具体差异，拒绝整类豁免。批量报告区分 passed、failed、unsupported、人工核对及未验证；过期通过不能复用。见 [validation.md](../core/yaya/references/validation.md)。

默认保护事实、归属、条件、否定、不确定性、数字、变量和输出契约；用户明确要求
改变时按授权处理。提示词改写后的执行效果需要另测。所有语言包初版保持 experimental，
包格式校验与母语审阅分别验收。

## 验收与维护

工程验收包括脚本回归、可复现构建、移动后的核心解析，以及隔离环境中的安装和回滚。
写作评测为每题创建独立上下文，分别检查语义、任务完成与文风。`tests/evals/cases.json`
覆盖五语言、四任务及反例。单元测试通过只说明相应程序行为符合预期。

无后台遥测。命令返回 JSON 状态及备份路径；排查时查看测试、构建和评审记录。
CI 已配置 Windows/Linux 和 Python 3.10/3.13/3.14 矩阵；远程运行结果需在提交后确认。
测试语料、工具、调研和运行证据集中在 [tests/](../tests/README.md)，不进入发布包。

默认编辑评测共 112 条：72 条去 AI 味、6 条跨场景和原有 34 条材料。生成时每题独立
上下文，保留无 Skill 对照、模型实际日志和首轮失败；中英文共同场景另与固定源码的
竞品指导对照。用例定义、生成完成、机械通过和匿名评审是不同状态，实际完成情况
以结果报告为准。
