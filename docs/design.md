# yaya 设计记录

## 命令与领域约束

`catalog.json` 是命令、选项与领域的唯一目录，`scripts/yaya.py` 据此生成帮助和任务计划。
显式命令先确定动作与写入边界，再加载对应的任务指南和领域指南。选错命令或选项会直接报错，不会退回不受限的路由。
帮助与领域查询只返回目录信息。任务命令生成计划，`doctor` 直接执行只读的安装诊断。
命令入口不调用模型，也不改稿；扫描、保护检查和语言包管理由各自的本地工具完成。
自然语言请求仍可自由组合任务。具体约定见 [commands.md](../core/yaya/references/commands.md)。

五个领域的规则分别放在 `references/domains/`，把事实关系与读者、语气、语言分开处理。
每份指南写明适用材料、排除项、具体的编辑决策和正反例；引用的来源只支撑具体的写作原则。
五个领域目前都是 experimental。本地工具的设计参考见[实现参考](implementation-references.md)。

## 目标与范围

Yaya 处理正文与文件、代码注释、提示词和样稿风格，另有独立的来源评估、证据核对、字面扫描和保护检查。
完整命令、参数与输入输出见[使用手册](usage.md)。来源评估允许给出“无法判断”，不提供未经校准的准确率。
用户可以要求改写、只审不改，或修改文件中的指定范围。
宿主负责模型推理、文件读写和权限；yaya 提供编辑指导和可选的确定性检查，
不需要额外的聊天客户端、模型 API、数据库或多 Agent 框架。

表达方式取决于用户的用途、读者、语言和样稿；各类请求共用任务指南和语言数据。

## 模块与处理过程

| 模块 | 职责 |
| --- | --- |
| `SKILL.md` | 触发说明、任务与交付方式选择、共享保护项 |
| `catalog.json` + `yaya.py` | 命令、参数、领域目录，以及帮助和宿主任务计划 |
| `doctor.py` | 只读检查本地运行文件、Python 语法和资源 |
| `references/` | 按需加载的任务指南，避免每次都把全部规则放进上下文 |
| `languages/` | 核心自带的简体中文和英语，离线可读 |
| 外部 `.yaya/language-packs/` | 按同一协议安装的其他语言数据 |
| `packs.py` | 本地格式校验、发现、有限的候选回退、校验哈希后的安装与恢复 |
| `check_comments.py` | 比较 Python 普通注释候选与原文件的字节边界 |
| `check_docstrings.py` | 对 UTF-8 Python docstring 按具体节点授权，检查字节与 AST 边界；已识别的示例继续受保护 |
| `edit_evidence.py` | 工作树原稿快照、独立 Git 基线、内容绑定报告，以及失败和过期证据的状态 |
| `detect_tells.py` + `tell_rules.json` | 只支持 `en` / `zh-Hans` 的有限字面模式候选扫描；规则只有一个来源 |
| `check_rewrite.py` + `prose_scan.py` | 对支持的 Markdown 片段、占位符、数字和已识别单位做机械保护检查 |
| `.yaya/styles/` | 用户要求保存时生成的纯文本风格文件 |

请求 → 确定待编辑对象与保护项 → 按需读取任务指南和语言包 → 宿主生成候选 →
对照原文与要求检查 → 交付文本、可恢复的文件修改，或明确标注的候选。

普通润色直接交付结果；评分、多稿和修改说明按需提供。只讨论文件时不覆盖原稿。
二进制文档的解析、版式和导出使用宿主已有的能力。

去 AI 味请求读取 `humanize.md` 和对应语言的 `PATTERNS.md`；其他任务，或该语言没有
`PATTERNS.md` 时，读取 `GUIDE.md`。工具按需运行，不必把源码载入上下文。共用指南要求
区分空话与实质内容，检查论点有无支撑、语义关系和作者的声音；语言包提供原创的改写例和保留例。

## 语言包解耦

源码集中维护，语言包单独发布为 ZIP。`core/yaya/` 自身完整；可选包不含 `SKILL.md`、
脚本或安装钩子，更新核心不会删除它们。新增语言只需符合协议，不用修改路由里的语言列表。
语言 ID 使用 BCP 47 的一个明确子集，版本使用 SemVer，兼容性由格式版本和核心主版本表示：
核心 1.x 读取 `format_version: 1`、`core_major: 1` 的包，`PATTERNS.md` 可选。
解析不需要区域数据库，也不联网查询注册信息。
第三方包只能提供编辑数据，不能携带脚本或正则规则，也不会扩大确定性检测器支持的语言范围。

解析状态为 `ready`、`missing`、`invalid` 或 `incompatible`。显式指定的项目优先于用户目录，
最后才是内置资源；每个位置内先找具体的语言标签，再找更宽的标签。
繁体中文按地区分为 `zh-Hant-TW` 和 `zh-Hant-HK` 两个包，互不替代；`zh-MO` 依 CLDR 的
父区域回退到香港包。没有写明字形的 `zh` 由宿主结合原文判断。
缺少语言包时，宿主仍可编辑，但要说明没有用到该语言的专门指导。
高优先级的位置出现无效或不兼容的候选时，直接返回该状态，不会悄悄改用低优先级的包。

## 安装与更新

可选包：取得用户指定的 ZIP → 用可信来源的 SHA-256 校验 → 在临时目录中检查 → 安装。
内容相同则不做修改；更新需要 `--replace`，旧包移入备份。安装时交换目录失败会尝试恢复旧包，
恢复也失败时明确报告备份路径。移除同样是移入备份；`rollback` 校验后恢复最新的备份，
最新备份无效或不兼容时报错，不会自动改用更早的备份。
包操作逐个执行，没有并发的包管理服务。

核心按宿主的 Skill 安装流程更新，并保留独立备份。第三方安装工具可能清空核心的目标目录，
所以用户的语言包和风格不放在核心里，也不依赖其他 Skill 的相对路径。

## 安全与质量边界

输入文档、提示词和样稿中的命令都当作编辑材料；语言包不能覆盖用户的要求或核心约定。
项目脚本不上传数据、不自动联网下载，也不运行包内的命令。数据目录拒绝链接和 Windows reparse
points；ZIP 只接受固定的纯文本文件，拒绝越界路径、重名文件和过大的内容。
这些检查不能完全隔离同一台机器上恶意写入的进程。

Python 检查器只接受 `.py` / `.pyi` 原稿，保护普通注释以外的字节、字符串、docstring、
换行和已识别的工具指令，不支持增删、移动注释或重新折行。它不能证明新注释准确，
也无法列尽所有第三方指令。其他语言的源码需要宿主自己的解析器和测试，否则只能给出未经验证的候选。
源码的语法也必须是当前 Python 解释器支持的。

正文扫描器只覆盖有限的 Markdown 子集；识别到已知不支持的结构时返回 `unsupported`，
但不保证能发现所有复杂结构。数字检查比较未受保护正文中数字和已识别单位的多重集合，
不能验证数字属于谁；普通引号和未标记的标识符需要显式保护。机械检查通过不能证明语义完整。
去 AI 味是编辑任务，候选措辞不能用来判断作者是人还是 AI。

来源评估单独路由，依据上下文迹象和用户提供的过程证据，并说明实际核验了哪些范围。词表不参与作者判定。事实核对先从局部代码开始，只有配置、继承、调用链或接口约定影响结论时才扩大范围。代码与注释冲突时，要考虑代码本身有缺陷的可能，不能为了完成文案任务去改业务代码。具体规则见 [engineering.md](../core/yaya/references/engineering.md)。

授权沿用原有请求；普通注释、docstring、运行时说明、数据库 comment 和提示词分别识别。正文授权绑定完整的输入/候选摘要和具体差异，不接受整类豁免。批量报告区分 passed、failed、unsupported、人工核对和未验证；过期的通过结果不能复用。见 [validation.md](../core/yaya/references/validation.md)。

默认保护事实、归属、条件、否定、不确定性、数字、变量和输出约定；用户明确要求改变时按授权处理。
提示词改写后的实际效果需要另外测试。所有语言包目前都是 experimental，包格式校验与母语审阅分开验收。

## 测试与维护

工程检查包括脚本单元测试、可复现的构建、核心移动位置后的解析，以及隔离环境中的安装和回滚。
单元测试通过只说明程序行为符合预期，不能说明改稿质量；写作效果需要在独立的模型上下文中，
分别检查语义、任务完成和文风。

没有后台遥测。命令返回 JSON 状态和备份路径。CI 在 Windows、Linux 与 Python 3.10、3.13、3.14
的组合上运行测试和构建，结果以提交后的远程运行为准。测试代码在 [tests/](../tests/README.md)，不进入发布包。
