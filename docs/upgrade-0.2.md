# 0.2 升级说明

0.2 增加去 AI 味指导、只审不改模式和可选正文检查器，保留代码注释、提示词及风格学习。
本文保留 0.2 的设计和验收记录；当前版本用法见[使用手册](usage.md)，升级步骤见[0.5 说明](upgrade-0.5.md)。

## 0.2.1 工程保真与“这是 AI 吗”

当时的核心为 0.2.1，可选语言包为 0.2.0。入口保持按需加载；纯润色、带证据编辑、只读审阅分别处理，普通编辑直接交付。新增 [工程保真](../core/yaya/references/engineering.md)、[独立 docstring 与批量证据](../core/yaya/references/validation.md) 和 [作者来源审阅](../core/yaya/references/authorship.md)。

普通注释校验不放宽。docstring 使用独立的具体节点与候选摘要授权；数据库元数据、运行时字符串和业务代码不随普通注释任务获得授权。正文 `--allow` 不再接受整类放行，旧命令需迁移为具体差异清单。检查只证明机械范围，事实与语义另审。

“这是 AI 吗”评估写作迹象和来源材料，允许无法判断，不提供未经校准的概率或准确率。详细验收、失败与未覆盖边界见 [0.2.1 验收记录](../tests/results/2026-10-21-engineering/README.md)。下文保留 0.2.0 的历史设计与结果。

## 从参考项目中采用什么

| 参考方向 | 本次实现 | 判断依据 |
| --- | --- | --- |
| Humanizer 的具体模式与声音匹配 | 中英文专项给出原创改写例、保留例；已有声音优先 | 同一句式可能是空话，也可能表达真实对比 |
| Humanizer-zh 的中文专项 | 处理密集修饰、“进行 + 动词”、机械过渡、翻译腔等 | 不把英语词表直接翻译成中文禁词表 |
| avoid-ai-writing 的只检测与保护检查 | 自然语言审稿；可选候选扫描；独立机械校验 | 先区分读者体验、语义保真和可机械验证的片段 |
| 轻量规则集的上下文控制 | 短入口、一个任务参考、按语言选择专项或指南 | 不要求每次加载全部规则或启动额外模型 |

源码核查和固定修订见 [调研记录](../tests/research/humanize-upgrade.md)。
按需加载与验证方式另对照了 [官方 Skill 文档](../tests/research/official-skill-guidance.md)。
新指导和示例自行编写；竞品原文及 MIT 许可证只作为隔离评测输入保存。

## 用户如何使用

| 请求 | 行为 |
| --- | --- |
| “去掉这篇文章的 AI 味” | 删空泛铺垫，必要时重组句子，保留论点、证据、归因和有用细节 |
| “先看看哪里有问题” | 引用具体文字，说明阅读问题及建议方向；不交付替换全文 |
| “金融领域风格，普通读者也能懂” | 兼顾专业准确性和读者理解，不添加来源中没有的数据 |
| “只改这个文件的简介” | 先读文件，保存可恢复原稿或 diff，仅改授权范围 |
| “优化这个提示词，去掉空话” | 改写提示词本身，保留变量、行为顺序、工具权限和输出约定 |
| “让 AI 以后按这种风格回答” | 改相应输出风格指令，明确区分与提示词措辞优化 |
| “改代码注释” | 结合代码解释实际行为，保护代码和工具指令；Python 提供字节范围检查 |
| “学这段话的风格” | 提炼有证据的表达习惯；按要求应用或保存，不迁移样稿的身份和事实 |

按请求决定改动幅度：语气转换应落实，已清楚且符合要求的文字可以保留。
去套话时保留文章的实质内容，不擅自缩成摘要或补写故事、情绪和数字。

## 实现与扩展

请求进入 `SKILL.md`，按任务选择参考文档，再解析语言包。去 AI 味优先读
`PATTERNS.md`，缺少时或其他任务读 `GUIDE.md`；需要额外地区细节时再补读。宿主负责生成、
文件访问和权限，工具负责可确定的检查。

三个检查器均只读文件：

- `detect_tells.py`：仅支持 `en` / `zh-Hans`，扫描少量字面候选并保留位置、规则和局限；没有命中也不等于文字优质。
- `check_rewrite.py`：比较支持的 Markdown 片段、数字及已识别单位、占位符等；识别到已知不支持结构时明确返回，但不是完整 Markdown 解析器。
- `check_comments.py`：限制 Python `.py` / `.pyi` 普通注释的字节修改边界，不支持增删、移动或重新折行注释；语义准确性另行审核。

数字检查仅比较未保护正文中的数字与已识别单位多重集合，一致不能证明归属、顺序和
否定正确。普通引号内容和指定原样片段需显式保护。去 AI 味是编辑表达，不判断作者
是人还是 AI。机械校验和编辑判断分别记录，并保留工具返回的 `limitations`。

默认核心包含简中和英文。繁中、日语、韩语独立下载；新语言通过同一包规范扩展。
核心 `0.2.0` 使用唯一的当前格式：`format_version: 1`、`core_major: 0`，允许可选
`PATTERNS.md`。包是纯数据，不携带脚本、正则或安装钩子，也不会扩展确定性检测器。
所有语言保持 `experimental`，直到取得相应人工语言审阅证据。

## 验收结果

确定性检查覆盖包安装、恢复、路径与大小限制、注释范围、Markdown 边界、CLI 错误
和可复现构建。编辑评测集中在 `tests/`：112 条合成用例按题隔离生成，对照不加载
Skill 的同一模型；60 条中英文共同场景另比较固定修订的 Humanizer / Humanizer-zh。
竞品比较不使用它们未声明支持的代码注释、提示词或其他语言任务来增加胜场。

匿名评审分别检查原意、任务完成和表达质量，记录胜、平、负及硬项失败。
首轮结果完整保留，修复后的复测单独存放；用于调参的用例归入回归集。

已执行检查的完整证据见 [0.2 验收报告](../tests/results/2026-10-20-upgrade/README.md)：

- 191 项脚本回归零失败，8 项因 Windows 链接权限跳过；最后两份指导澄清后另通过结构及发布检查。
- 修正前 112 题主对照为 14 胜、5 负、93 平；60 题竞品对照为 4 胜、2 负、54 平，尚未证明全面领先。
- 澄清整句空泛评价的处理后，10 题定向复测被模型评为双方硬项 10/10；复核保留判据不一致与可能漏判。
- 英文单题补测保留一次硬项失败。逐字复核发现，同一对成稿此前得到相反判断，不能选择性使用评分。
- 四组提示词下游执行中，原稿和改稿各 4/4 满足本次契约；不据此推断泛化质量提升。

发布前仍需跨模型重复运行与母语编辑抽查。

## 更新与回滚

核心替换前保留旧目录到 Skill 发现路径之外。语言包和用户保存的风格在独立数据目录，
核心更新不会覆盖。包内容更新保留备份，`packs.py rollback` 只验证并恢复最新备份；
该备份无效或不兼容时会报错，不自动寻找更旧备份。失败时保留报告中的恢复路径。

目前尚未公开发布，无需维护草稿格式迁移。发布后的兼容性变更须提供对应升级路径。
