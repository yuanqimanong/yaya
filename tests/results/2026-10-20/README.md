## 从参考项目采用了什么

本轮读取了 shuorenhua、avoid-ai-writing、speak-human-tw、your-voice、humanizer 的公开评测代码或记录，未运行这些外部项目。固定提交的源码证据见[调研报告](../../research/reference-evaluations.md)。

采用了四项做法：

1. 事实和任务要求作为硬项，表达偏好另外判定。
2. 包含需要改的文本、已经清楚的文本，以及不适用编辑 Skill 的任务。
3. 同宿主模型做有无 Skill 对照，生成阶段不提供评审条件，之后匿名评审。
4. 保存首次输出、失败和运行快照，修复结果另存。

没有引入词语命中分数或“AI 写作概率”。评测工具放在 `tests/`，不成为产品依赖。

## 已确认的问题与修复

### 打包输出可能进入源码目录

旧检查禁止输出到 `core/yaya/`，却允许输出到它的父目录 `core/`。隔离副本中的回归用例复现了错误写入。现在构建前拒绝整个 `core/` 子树，回归通过。

### 核心版本元数据校验不严格

旧代码会把布尔值或浮点值当作合法的整数兼容性字段；重复 JSON key 被覆盖，缺字段或错误类型可能产生 traceback。现在使用严格 JSON 读取，检查必需字段、整数类型、SemVer 与核心主版本。在创建输出目录前返回明确错误。

以上修复的首次证据与新增用例见[脚本修复记录](helpers.md)。最后一次完整回归另外保存在 `final-checks.*`，未覆盖之前的记录。

### Python 3.14 模板字符串的保护

静态检查发现 t-string 插值表达式也可能暴露源码文本。已将 `TSTRING_START/END` 纳入原有 f-string 注释保护，并增加 Python 3.14 条件测试。**本机没有可用的 3.14 解释器，该分支尚未实跑。** 这是保守补强，不记作已复现并验证的修复。CI 矩阵已补充 3.14，等待远端执行。

### 评测工具的完整性

新增准备、收集和汇总脚本，以及 6 个协议测试。拒绝缺题、重复 ID、未知 ID、空输出、重复 JSON key、非法判分和用偏好覆盖硬失败。新 protocol 2 校验 Skill、请求、评审条件和外部语言包哈希。

[协议 smoke 记录](protocol-smoke.json)使用人工构造的输出验证工具串联，明确不计入模型评测成绩。

## 编辑对照说明

26 条原有回归覆盖简中、英文、繁中、日语、韩语的正文、注释、提示词和风格提炼，以及混合语言、原文内指令和输出风格范围。另加 8 条用例，覆盖 README 不添设问、财务数据配对、只评不改、明确翻译、TypeScript 注释、日文不改、普通代码创建和不持久化风格。

对照使用继承的同一宿主模型，没有另选模型。每批最多 5 题，两组分批相同，共 14 个全新生成上下文。**同批共享上下文，每题只运行一次。** 因此 68 份输出不是 68 次独立试验，不能据此推断跨模型稳定性。精确模型修订和采样参数未由宿主提供；完整工具会话没有独立归档。用例 ID 保留在请求包里，生成者没有看到 `checks`。

三位新上下文评审者分别读取随机 A/B 输出、原文、请求和评审条件，不读取 Skill、条件映射或执行者 notes。主代理复核了具体问题与偏好理由，未改动原判。此处是模型评估，没有母语人工校准。

唯一明确硬失败在 baseline 的 `en-comments`：

```python
return items.get(key)
```

输入未说明 `items` 类型，对照输出却写“缺键返回 None”。yaya 保留了 `get` 方法契约未知的边界。这个用例与运行指南中的例子相近，属于回归证据，不能当成独立泛化证明。

9 个偏好 yaya 的案例主要是注释边界、风格提炼和例子来源说明。baseline 在面向新手的翻译题里解释了“回滚”，评审认为更有帮助。其余 24 题持平。本轮没有据此扩写通用写作规则，也没有把单个偏好变成强制模板。

两条“清楚就不改”均保留原文。普通算术和代码创建正常完成；`skill_used` 仅是执行者记录，不能替代真实宿主的自动触发率测试。已通过的“不保存风格”题也不能仅凭最终文本证明不存在其他文件操作；真实保存位置与既有文件保护另由文件集成测试核验。

## 下游与最终版本的对应

提示词执行检查覆盖：有材料时的 3 点 JSON 摘要及 20 字上限、无材料时只问一个问题并等待、两项 JSON 风险、缺页码时的通俗算法说明。原版和改写版均满足本次条件。结论是这些样例没有观察到契约回退，不能声称执行效果普遍提升。

首轮写作快照早于脚本修复；最终核心与首轮快照的差异只有 `packs.py`、`check_comments.py` 和注释指南的 t-string 说明。四类写作的主要规则没有改动。最终检查器对全部已有注释输出再次核验，结果仍为 Python 10 对通过、TypeScript 2 对 unsupported，见[复核记录](full/final-checker.json)。真实文件测试使用了更新后的核心快照。

首轮 protocol 1 在运行前保存了 Skill 哈希，但评审条件未提前哈希；收集时核对了两组完整生成请求与用例一致。不能将后来 protocol 2 的保证追溯到首轮。
