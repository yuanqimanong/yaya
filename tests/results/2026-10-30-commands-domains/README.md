# yaya 0.3.0：显式命令与五类领域规则

本轮实现并安装了八个显式命令，以及 `tech`、`finance`、`data`、`academic`、`business`
五类编辑规则。`catalog.json` 同时驱动帮助、选项校验和任务计划；自然语言仍可组合任务。
终端工具只解析计划，实际编辑由宿主模型执行。所有领域保持 **experimental**。

## 可确认的交付

- `polish`、`human`、`review`、`verify`、`comment`、`prompt`、`style`、`origin`。
- `--help`、`help COMMAND`、`COMMAND --help`、`domains [ID]` 与 JSON 目录。
- 未知命令/领域、冲突选项、只读命令写入请求会失败；输入材料中的选项不会扩大任务范围。
- 领域、读者、语气和语言独立选择。提示词区分措辞与下游输出风格，注释区分普通注释和 docstring。
- 五份领域指南分别说明覆盖、排除、保护关系、具体表达决策、原创例子和来源依据。
- 核心构建包含 41 个运行文件，本机安装逐文件核对 SHA-256，与最终源码一致。

设计来源与取舍见 [调研记录](../../research/commands-domains.md)。外部资料支撑写作原则，
不认证 yaya 的领域能力；没有复制第三方代码或将竞品成绩移用到本项目。

## 实际模型运行与复核

首轮预先声明 27 条案例和评审条件，由三个独立新上下文分别执行 9 条。
生成包只包含请求与原文，生成者读取冻结 Skill；评审者另读请求、原文、完整输出和评审条件，
不读 Skill 或实现。目录没有物理隔离，未导出完整工具事件流；执行文件是代理的活动记录。

首轮独立模型判断为：保真 26 pass、1 uncertain；任务 26 pass、1 uncertain；
表达 14 improved、5 preserved、8 not-applicable。原始判断见 [首轮评审](review-initial.json)，
没有把 uncertain 改写为原评审的 pass。

### 发现与修正

- **TECH01：实际保真问题。** 原文仅说 `CACHE_TTL` 可以覆盖默认值，首轮输出补充了“环境变量”。
  主代理据源文将该问题按失败处理：命名不能确定传入机制。技术指南增加一条有针对性的约束。
- **CMD04：执行声明证据不足。** 首轮评审无法仅凭 notes 证明内存检查发生过，故任务为 uncertain。
  主代理随后把原文和真实候选保存为文件，调用 `check_comments.check_files` 重新核验，得到 passed。
  这证明该候选的机械边界，不追认未导出的历史工具事件。

修订后用新上下文重跑 6 条受影响的技术案例，并增加 2 条配置来源控制例：
来源未知时不得推断，来源已给出时应准确保留。8 条独立复核的保真与任务均 pass；
表达为 6 improved、1 preserved、1 not-applicable。见 [复测输出](outputs-retest.json) 和
[复测评审](review-retest.json)。两个新控制例是在观察失败后设计的回归案例，不称为未见留出集。
合计 35 次案例执行，覆盖 29 个唯一案例；首轮被替代的输出仍完整保留。

### 候选的机械保护

首轮对适用的 18 份真实候选运行正文或注释检查，18 passed。TECH01 的新增推断仍能机械通过，
说明数字和代码保护不能替代语义复核。

复测对适用的 6 份候选执行检查，原始结果为 4 passed、2 failed。两处失败分别是给已有
`CACHE_TTL`、`config.json` 和 `TIMEOUT` 加行内代码标记；标识符内容和事实关系未变。
主代理按聊天润色允许的具体排版变化逐项复核，保存绑定原稿/候选 SHA-256 的精确授权，
重新检查两项均 passed。原失败和精确授权同时保留；没有整类放行，也未删除失败记录。

只读评审、来源审阅和包含原始证据材料的改稿没有冒充全文机械比对通过。
执行 notes 中有个别“人工对照”措辞，实际是模型自行复核，没有真人编辑参与。
首轮 CMD09 的 `exit_code=1` 是 PowerShell 外层观测；生成者没有读 `$LASTEXITCODE`。
直接 Python 子进程错误码由确定性测试核实为 2，两个口径未混用。

## 证据与限制

- [首轮完整输出](outputs-initial.json)、[复测完整输出](outputs-retest.json)：保留原始答复和执行者 notes。
- [原始证据归档](execution-evidence.zip)、[成员摘要](archive-index.json)：两轮 Skill 快照、请求、标准、输出、执行记录、评审、机械候选/报告及首轮/最终脚本日志。
- [最终运行文件摘要](runtime-sha256.json)、[安装记录](installation.json)：绑定最终安装内容与安装后检查。
- [隔离回滚验证](recovery-validation.json)：实际恢复原字节、移除本次新增文件及后续编辑保护的结果。
- 真实文件调用的完整回复、原稿、修改后文件和独立复查保存在归档的 `installed-file-smoke/`。

准备器也生成了 baseline 请求包，**baseline 没有运行**。本轮不宣称相比旧版有统计显著提升，
也不提供领域准确率。每批共享上下文、每个条件仅一次有效输出；精确服务端模型修订和参数未暴露，
未人为指定替代模型。评审也是模型判断，未经行业专家或母语编辑校准。

已测试中文和英文的有限合成素材；其他语言沿用自身语言包的质量边界。
提示词案例验证改写后的指令与输出契约，未重新执行下游金融/研究任务。
五类领域均是编辑支持，不能外推为投资建议、会计审计、生产验收、法律/医疗能力或全学科认证。

## 本机回滚

旧安装完整保存在 `D:/AIProjects/yaya/.yaya/upgrade-20261030/installed-before`；
源码原稿和逐文件内容绑定记录在同一恢复目录。默认只预演：

```text
python .yaya/upgrade-20261030/restore.py --scope installed
python .yaya/upgrade-20261030/restore.py --scope source
```

加 `--apply` 才执行恢复。脚本先检查所有目标的当前摘要，拒绝覆盖后续修改；只恢复本轮文件，
不执行 Git reset。恢复资料属于本机工作区，不在公开发布 ZIP 中；其他机器应按 INSTALL.md
保留自己的旧安装。未创建提交或发布远端版本。
