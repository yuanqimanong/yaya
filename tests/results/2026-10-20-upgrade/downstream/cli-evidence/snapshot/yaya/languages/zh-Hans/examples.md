# 简体中文教学示例

以下内容均为虚构教学材料；没有可供补充的外部事实。改写只使用每例给定的信息。

## 1. 金融风格润色文本

输入：公司这次收入是 1.2 亿元，比去年同期增长了 8%，毛利率从 20% 到了 23%。公司觉得需求可能回暖，但目前没有提供订单数据。

可接受：公司本期收入为 1.2 亿元，同比增长 8%；毛利率由 20% 升至 23%，提高 3 个百分点。公司认为需求可能回暖，但尚未提供订单数据。

不可接受：公司业绩强劲增长，订单持续回升，需求已经复苏。

原因：后者添加了订单事实，将可能性改成确定结论。百分点变化可由输入直接计算。

## 2. 计算机领域风格重写注释

输入：

```python
def should_retry(status):
    # 这里非常智能地判断一下这个状态是不是需要重试的状态
    return status == 429
```

只将注释改为：`# 状态码为 429 时返回 True，表示应重试。`

不可接受：`# 服务器出错时自动重试，直到成功。`

原因：可见代码只判断状态，没有执行重试，也未规定次数。函数和代码保持不变。

## 3. 去除提示词套话

输入：你是顶级的总结专家，请充分发挥你的能力，只依据 {{text}} 总结三点，每点不超过 50 字；材料不足时先问一个问题，收到答复后再总结。

可接受：只依据 {{text}} 总结三点，每点不超过 50 字。材料不足时，先提出一个澄清问题，收到答复后再总结。

不可接受：结合你的知识，详细总结这段文字。

原因：后者丢失变量、来源限制、数量、字数和等待答复条件。

## 4. 从样稿提取风格

样稿：先看能不能用。能用，再看哪里慢。没测过的地方，别急着下结论。

可迁移偏好：短句；先后顺序明确；直接用动作开头；没有证据时保留判断。

新任务：生成一段要求模型检查所给日志的提示词。

可接受：先看 {{log}} 里有哪些错误。再按出现顺序列出。只用日志里的信息；不能确定的地方，明确说出来。

不可接受：我修过很多服务器，你可以相信我的结论。

原因：后者捏造身份与经历，也没有体现样稿的处理顺序。
