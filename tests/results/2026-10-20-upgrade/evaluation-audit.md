# 评测统计与证据链审查

范围：`collect.py`、`summarize.py`、`compare_runs.py`、`check_outputs.py`。只检查评测基础设施，不追加模型采样，不修改既有生成、评审或失败记录。

## 已修复

| 问题 | 可复现影响 | 修复与验证 |
| --- | --- | --- |
| 解盲映射没有验证一一对应 | A、B 都写成 `skill` 时，两份评级都累计到 Skill 组 | 要求每题恰好映射到 `skill`、`baseline` 各一次；错误映射测试 |
| 机械结果用字典推导收集 | 重复的 `(id, condition)` 静默覆盖先前记录 | 拒绝重复、缺失、未知状态；检查器 error 计 uncertain；覆盖回归测试 |
| 只检查发布输出的 JSON 格式 | CLI 完成后修改 `outputs.json` 仍可能进入评审 | 复用既有成功尝试验收，检查原始 final、日志、哈希与发布输出；复用结果回查源尝试 |
| 收集器可覆写已有匿名包 | 再次收集到其他结果目录时可能替换已评审材料 | 已有 `review/` 时直接拒绝 |

CLI 验收另存 `execution-audit.json`，本运行的进程调用数、首次失败、恢复调用和复用输出分开统计。基础设施恢复保留失败尝试，不计作独立重复试验。无 CLI 元数据的历史运行标为 `not_recorded`。

## 仍需正确解释的结果

- 全量生成与评审完成前不发布缺题的质量统计。成功执行、通过 JSON schema 与文字质量是不同结论。
- `hard_pass` 综合指定机械检查和模型的 fidelity/task 判断。它不是全自动语义证明；独立正文机械检查报告不自动改变模型评级。
- 机械 `failed` 可能来自用户授权的格式改动或完整回答中的解释包装。必须保留原结果并说明原因，不能事后删掉不利片段再重算。`unsupported`、`error` 不计入通过。
- 偏好必须同时展示 Skill、baseline、tie、uncertain 数量及题目分母。剔除持平后的胜率与全题胜率含义不同；不能替换分母后只报告更高数字。
- 现有材料是原创合成用例。已被用于开发或审查的题应作为回归集，不能再声称完全未见过的独立测试集。
- 单一模型、单次运行、同模型评审只能说明本次条件下的表现。它不能证明跨模型、母语人工偏好或“全场景超过所有竞品”。
- 竞品比较只适用于预先冻结的共同任务子集。未评测的注释、提示词、语言和工具场景不能用缺项推断竞品质量落后。
- 生成器由任务标签加载对应指南；这验证加载指南后的行为，不是宿主自然触发 Skill 的完整端到端召回率。`skill_used` 是自报字段。

测试记录见同目录 `unittest-final.log`。所有基础设施回归使用本地合成 CLI，不产生模型调用。
