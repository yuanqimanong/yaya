# Русские учебные примеры

Все примеры ниже вымышлены и служат только для обучения. При правке используйте лишь те сведения, которые даны в примере.

## 1. Финансовый текст

Вход: Выручка за квартал — 1,2 млн руб., это на 8 % больше, чем годом ранее. Валовая маржа выросла с 20 % до 23 %. Компания считает, что спрос может восстановиться, но данные о заказах не приводит.

Приемлемо: Выручка за квартал составила 1,2 млн руб. — на 8 % больше, чем годом ранее. Валовая маржа выросла с 20 % до 23 %, то есть на 3 процентных пункта. Компания считает, что спрос может восстановиться, но данные о заказах не приводит.

Неприемлемо: Выручка выросла на 8 %, валовая маржа выросла на 3 %, а спрос уже восстанавливается: заказы растут.

Причина: заказов в исходнике нет; 3 процентных пункта нельзя записывать как 3 %; «может» заменено на свершившийся факт.

## 2. Комментарий в коде

Вход:

```python
def should_retry(status):
    # Проверяет статус и решает, надо ли повторять запрос
    return status == 429
```

Правка только в комментарии: `# Для статуса 429 возвращает True: запрос имеет смысл повторить.`

Неприемлемо: `# Повторяет запрос при любой ошибке сервера, пока не получится.`

Причина: функция лишь сравнивает значение с 429 и ничего не повторяет. Ни цикла, ни других кодов ошибок в коде нет. Функцию и строку `return` не меняем.

## 3. Сжатие промпта

Вход: Ты — ведущий в мире эксперт по анализу текстов. Раскрой свой талант полностью. Опираясь только на {{text}}, составь конспект из трёх пунктов, не длиннее 50 слов каждый. Если материала не хватает, задай один уточняющий вопрос и дождись ответа, прежде чем писать.

Приемлемо: Опираясь только на {{text}}, составь конспект из трёх пунктов, не длиннее 50 слов каждый. Если материала не хватает, задай один уточняющий вопрос и дождись ответа.

Неприемлемо: Прочитай {{text}} и сделай подробный разбор в свободной форме.

Причина: потеряны опора на переменную, число пунктов, ограничение в 50 слов и условие с вопросом и ожиданием. «Подробный разбор» этим требованиям не отвечает.

## 4. Перенос стиля на другую тему

Образец: Сначала проверяем, что сборка проходит. Потом ищем, где она тормозит. То, что не проверяли, рабочим не называем.

Что переносится: короткие фразы, ясный порядок действий, глаголы в личной форме, трезвая оценка непроверенного.

Новая задача: собрать промпт для разбора лога {{log}}.

Приемлемо: Сначала найди в {{log}} ошибки. Потом расположи их в порядке появления. Используй только то, что есть в логе. Если данных для вывода не хватает, скажи об этом прямо.

Неприемлемо: Я много лет разбираю логи крупных систем, поэтому найду причину сбоя безошибочно.

Причина: во втором варианте придуманы опыт и гарантия результата, а манера образца не перенесена.
