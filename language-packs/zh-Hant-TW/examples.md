# 繁體中文（臺灣）教學示例

以下皆為虛構教學材料；改寫只使用各例提供的資訊。

## 1. 潤飾財務文字

輸入：本季營收為新臺幣 1.2 億元，比去年同期增加 8%。毛利率由 20% 升到 23%。公司認為需求可能回溫，但沒有提供訂單資料。

可接受：本季營收為新臺幣 1.2 億元，較去年同期成長 8%；毛利率由 20% 升至 23%，增加 3 個百分點。公司認為需求可能回溫，但尚未提供訂單資料。

不可接受：訂單強勁成長，顯示需求已全面復甦。

原因：後者新增了訂單事實，也把「可能回溫」改成確定的結論。

地區補例：原文寫「軟件更新」且使用者指定臺灣讀者時，可改為「軟體更新」。原文是香港新聞稿的引文時，保留「軟件」。

## 2. 改寫程式碼註解

輸入：

```python
def should_retry(status):
    # 這裡很聰明地檢查一下這個狀態是不是需要重試
    return status == 429
```

只把註解改為：`# 狀態碼為 429 時回傳 True，表示應該重試。`

不可接受：`# 遇到伺服器錯誤會自動重試，直到成功為止。`

原因：程式只比對一個狀態碼，本身不執行重試，也沒有設定次數。函式與程式碼保持不變。

## 3. 精簡提示詞

輸入：你是業界頂尖的摘要專家。請充分發揮你的專業，只根據 {{text}} 整理三個重點，每點不超過 50 字。如果資料不足，請先問一個問題，等收到回覆再整理。

可接受：只根據 {{text}} 整理三個重點，每點不超過 50 字。資料不足時，先提出一個問題，收到回覆後再整理。

不可接受：請運用你的知識，詳細說明這份資料。

原因：後者遺漏了變數、資料來源限制、重點數量、字數與等待回覆的條件。

## 4. 學習樣稿風格

樣稿：先確認能不能跑。能跑，再找哪裡慢。還沒測過的地方，先別下定論。

可轉移的偏好：短句、清楚的先後順序、直接描述動作、保留尚未確定的判斷。

新任務：寫一段檢查紀錄檔的提示詞。

可接受：先找出 {{log}} 裡的錯誤，再依出現順序列出。只使用紀錄裡的資訊；無法確定的地方請直接說明。

不可接受：我修過上百台伺服器，這種問題難不倒我。

原因：後者捏造了經歷與身分，卻沒有轉移樣稿的處理順序。
